# Gacha_Prototype

가챠(뽑기) 시스템 확률 설계 · Unity 프로토타입 구현 프로젝트입니다.
캐주얼 모바일 RPG 장르의 BM(확률형 아이템) 설계 역량을 보여주기 위해 제작했습니다.

설계는 기획자가 직접 하고 구현은 AI 코딩 어시스턴트(Claude Code + Unity MCP)를 활용했습니다.

## 확정 확률 설계

| 등급 | 확률 | 가치점수 | 기대값 기여 | 비고 |
|---|---|---|---|---|
| R | 60.0% | 1 | 0.60 | 기본 물량 보상 |
| SR | 25.0% | 4 | 1.00 | 중간 만족감 |
| SSR | 12.0% | 16 | 1.92 | 체감 성취감 구간 (등급 간 ×4 배율 유지) |
| LR | 3.0% | 64 | 1.92 | 벤치마크 대비 의도적으로 높게 설정 |
| **합계** | **100.0%** | – | **5.44** | |

- **천장(피티):** 60회 완전천장 (천장 없이 60회 내 LR 획득확률 83.9%)
- **재화 밸런스:** 뽑기 1회 200재화 / 일일 무과금 획득 300재화 → 천장 도달까지 약 40일
- **벤치마킹:** 나 혼자만 레벨업:어라이즈(SSR 1.2%), 원신(5성 1.6%)보다 확률은 관대하게, 가치점수는 ×4 배율로 설계해 상위 등급 확장 여지를 남김

## 구현 내용 (6단계)

1. 확률 설계 문서화 — 등급별 확률·천장·기대값 확정
2. `GachaTableSO` (ScriptableObject) 기반 데이터 구조 설계
3. `GachaDrawer` — 가중치 랜덤 + 천장 카운터 로직
4. `GachaUIController` — UI Toolkit(UXML/USS) 기반 결과 표시 화면. 좌(뽑기 액션) · 우(검증 시뮬레이터) 2단 레이아웃, 색상 토큰(`--color-*` 커스텀 프로퍼티) 기반 팔레트, 버튼 hover/focus/active/disabled 전체 상태 구현
5. `PlayerWallet` — 재화 소모·획득 흐름 연결
6. `GachaSimulator` — N회(100 / 1,000 / 10,000 / 100,000회 선택 가능) 반복 뽑기로 실제 확률 분포를 설계값과 비교 검증. 등급별 설계값 대비 편차(Δ) 표시, 천장 도달까지 걸린 뽑기 횟수 분포 히스토그램으로 천장 로직 준수 여부를 시각적으로 확인

100,000회 시뮬레이션 검증 결과: R 59.6% / SR 24.8% / SSR 12.1% / LR 3.6% (설계값 대비 오차 ±0.6%p 이내), 천장 위반 0건.

## 프로젝트 구조

```
Assets/
  Scripts/Gacha/     - 확률 데이터, 뽑기 로직, 재화, 시뮬레이터, UI 컨트롤러
  Data/Gacha/        - DefaultGachaTable.asset (확정 확률표 데이터)
  UI/Gacha/          - UXML/USS (결과 화면, 시뮬레이터 화면)
  Scenes/            - SampleScene (GachaUI 오브젝트 포함)
```

## 실행 방법

- **Unity 에디터:** Unity 6000.3.21f1 이상으로 프로젝트를 열고 `Assets/Scenes/SampleScene.unity`를 Play
- **빌드:** Unity 메뉴 또는 `manage_build`로 StandaloneWindows64 빌드 (결과물은 `.gitignore` 처리되어 저장소에는 포함되지 않음)

## 기술 스택

Unity 6000.3.21f1 · C# · UI Toolkit (UXML/USS) · ScriptableObject
